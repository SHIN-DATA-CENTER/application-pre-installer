# 構成と拡張

## 実行モデル

Slint UI → Rustの選択・同意管理 → 実行計画 → 標準アプリの削除 → ドライバー専用ワーカー → アプリ導入 → 結果記録。

SlintのイベントループからWindows処理をワーカースレッドへ渡し、メッセージで画面を更新します。画面を閉じる操作も、インストール中は中止要求として扱います。

`model` はカタログ・プロファイル・依存関係・状態の型と検証、`store` は排他起動・JSONの同期置換保存、`runner` は依存順実行・中止・再開、`platform` はWindows連携、`ui` は画面との接続を担当します。

画面は左側の手順表示、中央の作業領域、下部の状態・操作で構成します。アプリ選択では全件・選択中・独自登録の表示切り替えとタグ検索を左側に配置し、一覧取得・名前検索・プロファイル操作を同じツールバーにまとめています。行内の文字とボタンは縦方向の中央に揃え、長い説明や取得元は省略表示と詳細画面で扱います。並び替えはRustで行い、SlintのListViewで表示中の行だけを生成します。選択だけが変わった場合は既存モデルの該当行を更新し、スクロール位置を保持します。

## Windows連携

画面の操作欄は検索・一覧取得とJSON操作を2段に分けます。環境確認は自然な高さの情報表を中央にまとめ、表内部の大きな空白を避けます。確定操作はダイアログの右下へ揃え、最小サイズでもタグ欄と下部の操作が重ならない高さを確保します。

Rustから、EXEに埋め込まれた固定PowerShellスクリプトを起動します。Windows標準のPowerShell 5.1・CIM・COMを使用するため追加のランタイムは不要です。スクリプトはWMI/Windows Update Agent APIを呼び出します。msinfo32やデバイスマネージャーの画面は解析しません。

入力はJSONをBase64で環境変数に渡し、スクリプトのコードへ文字列連結しません。独自EXE/MSIはシェルを介さず起動します。PowerShell・cmd等のコマンド実行プログラムは登録対象外です。

ドライバーの昇格要求は同じEXEの `--driver-worker` へ渡します。ワーカーに任意コマンドを実行するインターフェースはありません。更新IDとリビジョンからWUAへ再問い合わせし、ハードウェアIDの一致・クラスの許可リスト・BIOS等の除外を改めて検査します。選択したドライバーは1回の昇格ワーカー内で順次処理します。キャンセルでは次の項目から開始を止めます。

`DriverProvider` は検索・導入・状態確認の共通境界です。メーカー拡張ではこの境界を実装し、同じ候補型と結果型に変換します。取得元ごとの署名・適合確認を省略しないでください。

`uninstall`は標準アプリの対応IDと削除条件を管理し、`AppRemover`で削除と状態確認を共通ランナーへ接続します。固定のAppxワーカーは現在の利用者だけを扱い、実行直前にも発行元を含むID・署名・状態・依存関係を再検証します。バンドルはその親パッケージを1候補として扱います。削除対象とアプリ内データの消失について確認画面で明示し、専用の同意がなければ実行しません。削除候補は持ち運び用プロファイルに含めず、端末ごとに再検出します。[詳細](windows-app-removal.md)

## データ形式

`search`は空白で区切ったAND / OR検索と、サイズ制限付きの正規表現を実装します。名前による補完は、レジストリを読む固定の`installed-names.ps1`から得た登録名とコミュニティの全件一覧を、UIで利用者が対応付けます。レジストリ値をシェルへ連結せず、名称一致だけでインストール対象とは判定しません。補完は元のJSONに対する確認済みIDの追加として再構築・検証し、複数登録の同一IDや取り消し時の元データの消失を避けます。登録名一覧全体や名前による推測は持ち運び用JSONへ含めません。

`transfer`はインストール済みアプリの読み取りと持ち運び用JSONを扱います。WinGet標準形式と本アプリのプロファイルを検証し、プレビューから選択へ反映します。`winget import`は直接実行しません。公式のwinget / msstoreソースだけを許可し、元のインストーラー追加引数は除外します。明示的なエクスポートでは選択と依存項目だけを保存し、内部のプロファイル保存では未選択の独自登録も保持します。[操作と制限](app-transfer.md)

カタログとプロファイルは `schema_version: 1` のJSONです。固定カタログは同梱しません。実行時に`winget search . --source winget`で全件取得し、取得時刻とともにローカルのJSONへ保存します。プロファイルは選択したアプリと依存項目のスナップショット・独自候補・更新設定を含み、ドライバーや利用規約への同意は含みません。取得した全件をプロファイルへ保存しません。既存のWinGet IDがキャッシュにある場合はキャッシュを優先し、プロファイルから導入方法を上書きさせません。不明フィールド・ID不一致・依存循環・スクリプト・不正URLは拒否します。

履歴には対象のコピーと状態を記録します。処理開始前に `running` を保存し、終了後に結果へ置換します。`success`・`skipped` は再実行せず、`running`・`reboot_required` は状態を再検査します。適用を確認できない処理を自動で再実行しません。失敗や確認不能の項目は利用者が確認後に新たに選び直します。

WinGet検索はローカライズされた見出し名に依存せず、見出しの表示幅から列を読みます。読み取り不能な形式ではエラーにし、省略されたパッケージIDをインストールしません。

現在のWinGetコミュニティ一覧には統一カテゴリーがないため、取得した項目は「未分類」とします。Microsoft Store側で取得できるカテゴリーとは区別します。タグの検索はWinGet自身に任せ、返されたIDの集合とローカル検索を組み合わせます。従来の4カテゴリーは独自登録・過去データの互換性のために保持します。インストール数・評価は現在の一覧のメタデータにないため、ソート用の架空データや代理指標を生成しません。

`tags`はタグ一覧の検証とキャッシュを管理します。固定のPowerShellワーカーが登録済みコミュニティ索引をWindowsのSQLiteで読み取り専用で開き、1系・2系の既知のタグ表を列挙します。WinGetの内部形式への依存はここに限定し、未対応形式ではキャッシュを保持して手入力の検索へ案内します。Slint側のタグ一覧は表示行のみ生成し、一覧の検索はローカルで行います。Storeとの自動照合や自動カテゴリー分類は実装していません。

WUAの `DriverClass` は `OtherHardware` 等のSUS分類であり、INF/PnPクラスと同一ではありません。分類の許可判定には、ハードウェアIDが一致するローカルPnPデバイスのクラスを使用します。分類不明や複数の異なるクラスへ一致する候補は拒否します。WUAの `ForceQuiet` を使用し、非対話での導入が失敗した場合も対話の強制や検証の回避は行いません。
