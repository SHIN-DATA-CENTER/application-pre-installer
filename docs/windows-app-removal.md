# Windows標準アプリの選択削除

v0.2.0で追加。画面は「環境確認 → アプリ選択 → 標準アプリの削除 → ドライバー選択 → 実行内容の確認 → 実行・結果」の6段階です。削除画面は検出・選択だけを行い、次へ進んだだけでは削除しません。検出を省略してアプリ導入だけを行えます。

## 対象

現在の利用者に登録されたAppx/MSIXのうち、実装で対応しているWindows標準アプリとパッケージ名・発行元IDが一致するものを表示します。天気、ニュース、Clipchamp、Xbox、Teams、Outlook、スマートフォン連携、付箋、To Do、フォト、ペイント、メモ帳、電卓、カメラ、Snipping Tool等が対象です。Windowsの版・更新・組織の設定により、表示されるアプリと削除可否は異なります。

固定のインストール候補を復活させる機能ではなく、実機で検出できたアプリのみ表示します。出荷時に存在したか、後から同じアプリを追加したかは識別できません。メーカー独自のWin32ソフト、すべてのStoreアプリ、Windowsの機能やシステム部品の一括削除には対応しません。

Microsoft Store、App Installer（WinGet）、シェル、ランタイム、コーデック、Gaming Servicesは対応IDの一覧に含めません。対応する名前でも、削除不可、フレームワーク、リソース、開発用、署名・状態が確認できないもの、ほかのアプリから参照されている依存先は選択できません。

## 操作と影響

1. 「標準アプリを検出」で候補を表示します。すべて未選択です。
2. 不要なアプリだけチェックし、詳細で正確なパッケージを確認します。名前でも絞り込めます。
3. 確認画面で対象と範囲を確認し、アプリ内のデータ・設定が失われる可能性と、処理の実行に同意します。
4. 削除 → ドライバー → アプリ導入の順に処理し、個別の結果を記録します。

アプリ内のデータや設定が失われる可能性があるため、必要なものは実行前にバックアップしてください。再導入はMicrosoft Store等で行えますが、公開終了・組織の制限やデータ復元の保証はできません。

削除は`Remove-AppxPackage -Package <検出した正確なPackageFullName>`で**現在の利用者だけ**に実行します。管理者としての実行は要求しません。`-AllUsers`や`Remove-AppxProvisionedPackage`を使用しないため、他の利用者や新規利用者向けの登録は変更しません。再配信やWindowsの更新により再び追加される場合があります。

## 再検証・失敗・再開

実行直前に現在の利用者とパッケージの正確なID、署名、状態、削除可否、依存関係を再確認します。更新等でIDが変わっていた場合は操作待ちにし、最新の別バージョンを勝手に削除しません。登録がすでにない場合はスキップします。

削除後は同じパッケージファミリーの登録がなくなったことを確認して成功とします。登録が残った場合は確認不能、Windows処理のエラーは失敗として理由を表示します。ほかの独立した項目は続行します。中止時は新しい処理の開始を止め、実行中の削除処理は完了を待ちます。

実行履歴には対象を保存します。中断された削除は再開時に現在の登録を検査し、自動で削除を繰り返しません。削除候補と削除への同意は持ち運び用プロファイルへ保存しません。別PCでは再検出・再選択します。

## 根拠

- [Get-AppxPackage](https://learn.microsoft.com/en-us/powershell/module/appx/get-appxpackage): 利用者に登録されたパッケージの列挙と種類の指定。
- [Remove-AppxPackage](https://learn.microsoft.com/en-us/powershell/module/appx/remove-appxpackage): 正確なパッケージ指定による現在の利用者からの削除。
- [Microsoftの標準アプリ削除資料](https://learn.microsoft.com/en-us/windows/configuration/policy-based-inbox-app-removal/policy-based-inbox-app-removal): 標準アプリの例。本アプリはこの管理ポリシーを設定せず、通常利用者向けのAppx操作を使用します。

実削除と復元の検証はクリーンVMでの公開前確認に残しています。開発PC上では読み取り専用の検出と、Appx操作をすべて置換した模擬テスト・デモ画面で検証します。
